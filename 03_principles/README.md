# 第三章：设计原则与方法论

本章总结构建生产级 Harness 系统应遵循的五大设计原则。

这些原则提炼自 Claude Code、OpenClaw 以及业界其他成功智能体系统的最佳实践，在看似不同的架构中都有体现，说明了它们的普遍性。

**约束优先(Constraint-first)** 强调，对智能体能力的合理限制往往比无限制地赋予能力更关键。明确的约束边界既保证安全性，也提高系统的可预测性。

**可验证性(Verifiability)** 要求系统的每一个操作都可审计、可重放、可验证。这既是安全合规的要求，也是快速定位问题的基础。

**渐进信任(Progressive Trust)** 描述如何从人工密集的管理模式逐步演进到自主执行模式，这一过程应当可观测、可回退、循序渐进。

**故障假设(Design for Failure)** 要求设计时主动假设每一步都可能失败，并提前设计失败处理机制。这样即使出现意外，系统也能优雅降级而非彻底崩溃。

**智能体工学(Agent Ergonomics)** 要求为 Agent（而非人类）设计更好用的软件系统和开发工具：清晰指令、快速反馈、标准化接口。这一原则由黄东旭在 QCon 2026 提出，它提醒设计者，Harness 的“使用者”是自主智能体，而非有判断力的人类。

五大原则相互补充、相互强化，共同支撑一个安全、可靠、可管理且对 Agent 友好的智能体系统。

- 3.2：可验证性原则
