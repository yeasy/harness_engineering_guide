## 1.1 从大语言模型到智能体的快速过渡

单纯的模型能力不足以构建生产级应用；从大语言模型到完整的智能体系统，中间还需要 Harness 这一层。

### 1.1.1 问题的演变

大语言模型刚出现时，应用开发聚焦于模型本身：使用更大的模型、更好的提示词、更优质的数据。开发者期望通过改进模型，直接获得智能应用。

LLM 从实验室走向生产环境后，开发者遇到了意料之外的复杂性：

- **可靠性问题**：同样的问题，同一个模型的多次回答可能差异巨大，导致生产系统不可预测
- **外部交互问题**：LLM 只能生成文本，无法直接与真实世界系统交互。调用数据库、API、执行系统操作都需要额外的工程工作
- **成本控制问题**：大规模调用 API 的成本快速增长，需要更精细的控制和优化
- **安全性问题**：让 LLM 任意调用系统权限和外部接口存在严重的安全风险

为应对这些挑战，智能体的概念应运而生。智能体是指能够感知环境、规划行动、执行任务并从反馈中学习的自主系统。

### 1.1.2 智能体的三个核心能力

一个完整的智能体系统需要三个维度的能力：

**第一维：思维能力** 这是 LLM 的长项。借助提示词工程、思维链(Chain-of-Thought)、多步推理等技术，模型能够分解问题、规划步骤。

**第二维：行动能力** 这属于传统系统工程的范畴。智能体需要调用工具、操作外部系统、获取实时信息，这涉及工具注册、权限管理、结果验证等一系列机制。

**第三维：学习能力** 指从执行结果中获取反馈、调整策略、积累经验。这涉及记忆机制、强化学习信号、迭代优化等。

三个维度中，LLM 主要贡献第一维；第二维和第三维的实现质量决定智能体系统的成败。

由此得到本书的核心等式：

>**Agent = LLM + Harness**

大模型提供推理和决策的“大脑”，而 Harness 提供感知、执行、记忆和安全保障的“身体”。

模型决定了智能体的思维上限，Harness 决定了智能体的工程下限。一个没有 Harness 的大模型只是一台发动机，一个经过 Harness 工程化的智能体才是一辆能够可靠载人行驶的汽车。

### 1.1.3 为什么需要 Harness

一种朴素的看法是：大模型既然已能推理和规划，就无须再构建复杂的系统工程层。这种看法忽略了 **可靠性和可控性的鸿沟**。

以一个需要调用支付 API 的智能体为例。LLM 在推理中正确识别了支付金额、收款人等信息，但实际调用时仍面临以下问题：

- LLM 是否正确地以 API 期望的格式构造了请求？
- API 返回了错误状态码，智能体是否能够正确地理解和处理？
- 网络超时了，是否应该重试？重试多少次？
- 重复调用相同的支付请求是否会导致重复扣款？

这些问题无法依靠 LLM 的“聪慧”解决，需要系统工程层面的保障，这正是 Harness 的工作。

**Harness 不是要让智能体更聪明，而是要让智能体更可靠、更可控、更安全。**

它通过以下方式实现这一目标：

- **标准化的工具调用协议**：确保工具的输入输出格式一致、可预测
- **多层权限控制**：从 Ask-first（事前询问）/ Approve-once（任务级一次授权）到 Free（自动放行）的梯度化信任管理
- **执行结果的验证和反馈**：不仅记录智能体做了什么，还要验证它实际做了什么
- **故障恢复机制**：当某个步骤失败时，系统能够优雅地降级或恢复
- **完整的可观测性**：通过日志、追踪、指标等多个维度观察系统运行状态

### 1.1.4 本章的位置

本书假设读者对智能体的基本概念已有了解。关于智能体理论、多智能体协作、规划算法等深层内容，请参考 [《智能体 AI 权威指南》](https://yeasy.gitbook.io/agentic_ai_guide)。

本章及后续各章的重点是 **如何将理论上的智能体概念转化为生产级系统**，这一转化过程正是 Harness 工程要解决的问题。
